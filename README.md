# Разбор по дате рождения

FastAPI-сайт поверх трёх готовых расчётных движков: Матрица судьбы (нумерология),
Ба-цзы (китайская астрология), Джйотиш (ведическая астрология).

## Структура

- `engine/matrix`, `engine/bazi`, `engine/jyotish` — копии расчётных скриптов и
  справочников из скиллов `~/.codex/skills/*`. Логика расчёта не менялась.
- `app/services/*.py` — обёртка API над движками: `matrix_service.py` вызывает
  `calculate.py`/`render_html.py` напрямую как модуль, `bazi_service.py` и
  `jyotish_service.py` запускают свои скрипты подпроцессом и парсят JSON из
  stdout. `geocode_service.py` превращает город рождения в координаты и
  историческое смещение от UTC (см. ниже).
- `app/render/*.py` — печатные HTML-страницы результата (карточки, таблицы,
  кнопка «Скачать PDF» через печать браузера) для Ба-цзы и Джйотиш; страницы
  Матрицы судьбы и совместимости строит сам `engine/matrix/scripts/render_html.py`.
- `app/main.py` — FastAPI-приложение: JSON-эндпоинты для валидации
  (`/api/matrix`, `/api/bazi`, `/api/jyotish`) и HTML-эндпоинты с готовым
  разбором (`/api/matrix/html`, `/api/bazi/html`, `/api/jyotish/html`).
- `app/static/` — фронтенд без сборки: форма на три вкладки, после отправки
  переходит на готовую HTML-страницу с разбором.

## Город рождения вместо координат

В формах Ба-цзы и Джйотиш можно ввести город рождения вместо долготы/широты
и смещения от UTC вручную (ручной ввод остаётся под «Указать координаты
вручную» — на случай редкого места или расхождения с автоматикой).

Как это работает (`app/services/geocode_service.py`):
1. Название города → координаты через OpenStreetMap Nominatim (бесплатно,
   без ключа, но название города уходит на их сервер — это единственный
   внешний сетевой вызов в проекте).
2. Координаты → название часового пояса (IANA, например `Europe/Moscow`)
   через `timezonefinder` — офлайн, без сети.
3. Часовой пояс + дата/время рождения → фактическое смещение от UTC **на тот
   момент времени** через `zoneinfo` (использует базу IANA tzdata) — это
   само учитывает декретное/летнее время и все исторические переходы, без
   ручного гугления, как советовал делать сам скилл.

## Запуск

```bash

```

Открыть http://localhost:8000

Либо через Claude Code preview: `.claude/launch.json` уже настроен

## Статус движков

- **Матрица судьбы** — полностью рабочая, без внешних зависимостей.
- **Ба-цзы** — рабочий, зависит от чистого Python-пакета `lunar_python`
  (уже в requirements.txt).
- **Джйотиш** — код готов, но не запустится без пакета `pyswisseph`. На Windows
  под эту версию Python нет готового wheel — нужен компилятор
  (Microsoft C++ Build Tools), чтобы собрать пакет из исходников. До тех пор
  `/api/jyotish` возвращает понятную ошибку 400 с объяснением.

## Доступ по паролю

Весь сайт можно закрыть одним общим логином/паролем через `app/auth.py` —
это HTTP Basic Auth, включается переменными окружения `SITE_USER` и
`SITE_PASSWORD`. Если обе не заданы (как локально по умолчанию), сайт открыт
без пароля. Заданы — браузер спросит логин/пароль при первом заходе.

## Деплой на Render.com

В репозитории уже есть `render.yaml`, Render подхватит его автоматически.

1. Зарегистрироваться на [render.com](https://render.com) (бесплатно) и
   привязать свой GitHub-аккаунт.
2. New → Blueprint → выбрать репозиторий `destiny-calculators`.
3. Render найдёт `render.yaml` и предложит создать веб-сервис — подтвердить.
4. В настройках сервиса (Environment) задать `SITE_USER` и `SITE_PASSWORD` —
   это и есть логин/пароль, которые вы дадите людям.
5. После деплоя Render выдаст постоянный публичный адрес вида
   `https://destiny-calculators.onrender.com` — им и делитесь вместе с
   логином/паролем.

Бесплатный план засыпает после ~15 минут без запросов и просыпается
~30–50 секунд на первый заход после паузы — для теста и показа знакомым
достаточно, для постоянной нагрузки стоит перейти на платный план.
